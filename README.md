# ระบบจองคิวร้านตัดผม (Barber Queue System — Phase 1: Web + LINE OA)

ระบบรันคิวร้านตัดผมตามเอกสารข้อกำหนด **ระบบจองคิวร้านตัดผม.pdf** โดยในเฟสแรกประกอบด้วย:
1. **เซิร์ฟเวอร์คิวกลาง & ฐานข้อมูล**: ออกหมายเลขคิวไม่ซ้ำ (`001`–`999`) เรียงต่อท้ายคิวกลางเดียวกันทั้งคิวหน้าร้าน (`WALK_IN`) และคิวออนไลน์ (`LINE`)
2. **เว็บแผงควบคุมสำหรับช่าง (`/barber`)**: ใช้แทนปุ่มกดจริง (ปุ่มสีเขียวเพิ่มคิวหน้าร้าน + ปุ่มสีน้ำเงินไปคิวถัดไป) และจอเล็ก MAX7219 บนโต๊ะช่างโดยไม่ต้องมีขั้นตอนล็อกอิน
3. **เว็บจอแสดงผลหน้าร้าน (`/display`)**: ใช้แทนจอผนัง P10 แสดงคิวที่กำลังตัดปัจจุบัน จำนวนคิวรอ และแสดงหมายเลขคิวหน้าร้านที่เพิ่งออกใหม่ชั่วครู่
4. **ระบบ LINE Official Account (`/api/line/webhook` & `/line-simulator`)**: ลูกค้ากดรับคิว ดูหมายเลขของตน ดูจำนวนคิวข้างหน้า ยกเลิกคิว และรับการแจ้งเตือนอัตโนมัติเมื่อเหลือ 3 คิว, 1 คิว, ถึงคิว และการเรียกซ้ำตามกติกาที่กำหนด (โดยไม่ข้ามคิวเองเมื่อแจ้งครบ)

---

## การเริ่มต้นใช้งาน (Quick Start)

```bash
npm install
npm run dev
```

เปิดเบราว์เซอร์ไปที่:
- **แผงควบคุมช่าง (แทนปุ่มกดจริง)**: `http://localhost:3000/barber`
- **จอแสดงผลหน้าร้าน (แทนจอ P10)**: `http://localhost:3000/display`
- **จำลอง LINE OA ลูกค้า & ทดสอบการแจ้งเตือน**: `http://localhost:3000/line-simulator`
- **ตั้งค่ากติกาการแจ้งเตือน & รีเซ็ตคิว**: `http://localhost:3000/settings`

---

## การเชื่อมต่อ LINE Official Account จริง

1. คัดลอกไฟล์ `.env.example` เป็น `.env.local`:
   ```bash
   cp .env.example .env.local
   ```
2. ใส่ค่า `LINE_CHANNEL_ACCESS_TOKEN` และ `LINE_CHANNEL_SECRET` จาก LINE Developers Console
3. ตั้งค่า Webhook URL ใน LINE Developers Console เป็น:
   ```
   https://<your-domain>/api/line/webhook
   ```
4. ตั้งค่าปุ่มใน Rich Menu ให้ส่ง Postback Data (หรือข้อความ):
   - **รับคิว**: `action=book` (หรือข้อความ `"รับคิว"`)
   - **ดูสถานะคิว**: `action=status` (หรือข้อความ `"เช็คคิว"`)
   - **ยกเลิกคิว**: `action=cancel` (หรือข้อความ `"ยกเลิกคิว"`)

## วันหยุดและประกาศ LINE

- สำหรับฐานข้อมูลเดิม ให้รัน migration ที่ยังค้างตามลำดับใน `supabase/migrations` รวมถึง `20261125000000_holiday_booking_and_notifications.sql` ก่อน deploy เว็บ รุ่นนี้ใช้วันตามปฏิทินเวลาไทยเพื่อตัดสินการหยุดร้าน และใช้รอบเปิดร้านเดิมในการนับเลขคิวข้ามคืน
- ตั้ง `SUPABASE_SERVICE_ROLE_KEY` ฝั่งเซิร์ฟเวอร์บน Vercel เพื่อให้ webhook บันทึกผู้ติดตามและให้ cron อัปเดตสถานะส่งประกาศได้เมื่อเปิด RLS พร้อมกับตั้งค่า LINE ตามขั้นตอนข้างบน
- Vercel Cron เรียก `/api/cron/holiday-notify` เวลา 09:00 น. ตามเวลาไทย หากบันทึกวันหยุดของวันนี้ผ่านหน้าตั้งค่าหลังเวลานี้ ระบบจะส่งประกาศประจำวันเมื่อบันทึก ช่างยังเลือกส่งข้อความที่แก้ไขเองล่วงหน้าได้
- หากรอบเช้าตกหล่นหรือมีการเพิ่มวันหยุดในฐานข้อมูลโดยตรงหลัง 09:00 น. ระบบจะส่งประกาศที่ค้างเมื่อหน้าช่างหรือจอหน้าร้านโหลดสถานะคิว หากส่งล้มเหลว ระบบจะลองใหม่หลัง 10 นาทีเมื่อมีการโหลดสถานะอีกครั้ง หรือเรียก cron เดิมซ้ำภายในวันนั้นได้ หากตั้ง `CRON_SECRET` ให้ส่งส่วนหัว `Authorization: Bearer <CRON_SECRET>` ด้วย
- ระบบส่งประกาศให้รายชื่อลูกค้าจาก webhook และประวัติคิว โดยกรอง LINE ID ของช่างและบัญชีจำลองออก ระบบใช้การบรอดแคสต์ถึงผู้ติดตาม LINE OA ทั้งหมดเฉพาะเมื่อไม่มีรายชื่อลูกค้าและไม่ได้ตั้ง LINE ID ของช่าง

## API สำหรับเชื่อมต่อบอร์ด ESP32 ในเฟสถัดไป

เมื่อต้องการต่อปุ่มกดจริงและจอ P10 / MAX7219 ด้วย ESP32 ในเฟส 2 สามารถยิง HTTP Request เข้าที่เซิร์ฟเวอร์คิวกลางชุดเดิมได้ทันที:
- `GET /api/queue/state` — อ่านเลขคิวปัจจุบัน จำนวนคิวรอ และเลขคิวหน้าร้านล่าสุด
- `POST /api/queue/walk-in` — ปุ่มสีเขียว: ออกหมายเลขคิวหน้าร้านใหม่
- `POST /api/queue/next` — ปุ่มสีน้ำเงิน: ปิดคิวปัจจุบันและเลื่อนไปยังคิวถัดไป
